# Step 2b research: full-text ingestion (2026-11-04)

All probes ran 2026-11-04, keyless, a descriptive User-Agent with no email, 2-4 s apart per host. Scratch scripts are outside the repo.

## Recommendations

| Decision | Evidence |
|---|---|
| **Tier order: arXiv HTML, then Europe PMC JATS (if a PMCID exists), then PDF.** | §1, §3 |
| **Drop the arXiv LaTeX-source tier** (spec §9.1 wording changes). `robots.txt` disallows `/e-print` and `/src` for every agent. HTML already covers every paper probed, including 1999. | §1, §2 |
| **Honour arxiv.org `Crawl-delay: 15` for `/html` and `/pdf`.** Add `arxiv.org: [15.0, 1]` to `limits.yaml`; today the host falls to `default` (1 s). | §1, §5 |
| **Parse arXiv HTML with the LaTeXML classes** (`ltx_section`, `ltx_para`, `ltx_figure`, `ltx_bibitem` and so on) using `selectolax` or `lxml`. Take equations from `math@alttext`. | §1 |
| **Europe PMC JATS is a tier before PDF** for papers with a PMCID. Use `ET`/`defusedxml`; take the licence from `<license>`. Timeouts need to be generous (5-19 s) and 5xx is possible. | §3 |
| **PDF fetch: allow `application/pdf` and `application/octet-stream`, then require the `%PDF-` magic.** Check the type and size before reading the body. Add a per-hop host limit. Treat 403/429 as "blocked", with no retry. | §4 |
| **Robots: Protego 0.7.0** (BSD-3, no dependencies). Cache per host for 24 h. 4xx means allow all; 5xx or network error means disallow until it recovers (RFC 9309). | §5 |
| **Chunking: `semchunk` 4.1.1 (MIT) with a `tokenizers` counter on the Qwen3 `tokenizer.json`**, run per section. Not docling's HybridChunker, not chonkie. | §6 |
| **Run ingestion as a background job, not inline.** HTML and JATS take seconds; PDF takes 0.7-3.6 s per page; OCR takes 5-26 s per page. | §7 |

## 1. arXiv HTML (`https://arxiv.org/html/<id>`)

**Coverage: 15 of 16 probes returned 200** (the 16th was a made-up ID).
- Papers probed: 1706.03762, 2310.06825, 1512.03385, 2011.14522, 2208.01618, 2405.04434, 2501.12948, 2602.00001, 2511.00001, 2611.02500, 1003.1234, `hep-th/9901001`, `cond-mat/0601001`, `math/0211159`, and `2310.06825v1`.
- The pages carry "Generated by LaTeXML oxide 0.7.6". arXiv appears to have back-converted its archive, because a 1999 hep-th paper has full HTML. A sample of 16 gives a rough 90-100% coverage, not a hard number. Papers whose source is not TeX (PDF-only) are the expected gap, and none turned up. The fallback must handle 404.
- `9912.99999` (not a real ID) returned **404, a 6 KB HTML page with an empty `<title>`**. There was no redirect in any probe (`num_redirects=0`). Versioned IDs work and return the same document.
- **Size: 111 KB to 2.2 MB** (1706.03762 is 189 KB; 2011.14522 is 2.18 MB; 2611.02500 is 1.78 MB). The 5 MB cap holds for these, but figure-heavy papers could exceed it, so raise the cap for arXiv HTML to about 8 MB or accept the failure and fall back to PDF. Latency was 0.4-2.3 s. `content-type` is `text/html; charset=utf-8`.
- **Markup** (checked on 1706.03762):
  - Structure: `article.ltx_document`, `h1.ltx_title_document`, `div.ltx_abstract`, `section.ltx_section|ltx_subsection|ltx_subsubsection|ltx_paragraph`, each with `h2|h3|h4|h5.ltx_title` and a `span.ltx_tag_section` number.
  - Body text: `div.ltx_para > p.ltx_p`.
  - Citations: `cite.ltx_cite > a.ltx_ref[href="#bib.bibN"]`. Cross-references: `a.ltx_ref` with `ltx_ref_tag`/`ltx_ref_title`.
  - Figures: `figure.ltx_figure` with `img.ltx_graphics` (relative `src`, e.g. `1706.03762v7/Figures/x.png`), some as `object`/`svg`; caption in `figcaption.ltx_caption` with `span.ltx_tag_figure`.
  - Tables: `figure.ltx_table` wrapping `table.ltx_tabular` (`tr.ltx_tr`, `td.ltx_td`).
  - Equations: `table.ltx_equation`/`ltx_equationgroup`, rows `tr.ltx_eqn_row`, number in `span.ltx_tag_equation`. All 142 `<math class="ltx_Math">` elements carry `alttext` (LaTeX).
  - References: `section.ltx_bibliography > ul.ltx_biblist > li.ltx_bibitem[id="bib.bibN"]`, parts in `span.ltx_bibblock`, tag in `span.ltx_tag_bibitem`.
  - Noise to strip: footnote marks (`span.ltx_note`, `ltx_note_outer`), author blocks (`ltx_authors`), and the page chrome. `ltx_ERROR` appears 1-2 times in 3 of the 16 pages (failed macros); count it as a quality signal.
- **robots.txt (arxiv.org):** `User-agent: *`, **`Crawl-delay: 15`**, `Allow: /abs /pdf /html /list /archive`, **`Disallow: /e-print /src /ps /dvi /format /api /search /oai2 ...`**.
- **arxiv.org vs export.arxiv.org:** both sit behind Fastly with no rate-limit headers, and neither throttled me at 4 s spacing. The documented split is policy: export.arxiv.org is the API mirror (3 s per request, already in `limits.yaml`); arxiv.org is the crawl surface under the 15 s `Crawl-delay`. I did not measure the throttling thresholds.

## 2. arXiv LaTeX source (`/e-print/<id>`)

I did not fetch it: `Disallow: /e-print` applies to all agents (Protego `can_fetch` returns False for `/e-print/...` and `/src/...`; `/html`, `/pdf`, `/abs` return True). The usual formats (tar.gz, single gzip, PDF-only) were therefore not probed. **Drop the tier.** It would also need pylatexenc/plasTeX and macro handling, which the pre-rendered LaTeXML HTML already does.

## 3. Europe PMC JATS (`/europepmc/webservices/rest/{PMCID}/fullTextXML`)

- **Keyless, 200, `application/xml`.** Probes: PMC7261179 (271 KB, 19 s), PMC7648763 (88 KB, 5.4 s), PMC5334499 (74 KB, 5.3 s), PMC3000000 (39 KB, 15 s). So **latency is 5-19 s**.
- **PMC4000000 returned 500** (a JSON error). `MED/26017442/fullTextXML` returned 404.
- **PMID 26017442 (LeCun, Nature "Deep learning") has no full text.** The search API gives `isOpenAccess:N, inEPMC:N, inPMC:N`, with no PMCID. So only the open-access subset works, and the pipeline must first get the PMCID from the search `resultList` (`pmcid`, `isOpenAccess:Y`).
- **Structure:** `<article article-type=...>`, `front` (`article-id[@pub-id-type]`, `abstract`, `permissions/license`), `body/sec/title/p`, `fig/caption`, `table-wrap` (present in 3 of 4), `back/ref-list/ref`, `xref`, `supplementary-material`. `disp-formula` did not occur in the samples.
- **Licence:** `<license license-type="cc-by" xlink:href=".../by/4.0/">` in PMC7261179 and PMC5334499 (cc-by-nc). PMC7648763 and PMC3000000 have only free-text `<license>` with no `href`. Store the `href` when present, else the text, else "unknown".
- The `Set-Cookie: JSESSIONID` is sent; ignore it.
- **Recommendation:** make it a tier before PDF for biomedical papers with `isOpenAccess:Y`. It gives clean sections, tables and references, which the PDF path lacks (ADR 0005).

## 4. PDFs via `oa_url`

OpenAlex sample (`filter=is_oa:true,publication_year:2022-2025&sample=12&seed=7`): of 8 `best_oa_location`s, **only 4 had a `pdf_url`**; the others were landing pages (DOI, handle).

| URL | Result |
|---|---|
| jurnal.dokicti.org `/article/download/...` | 200 `application/pdf`, 346 KB, magic `%PDF-` |
| doi.org -> irjmets.com (302, 301) | 200 `application/pdf`, no content-length, 745 KB, cross-host |
| jait.donnu.edu.ua (302 to `/download/`) | 200 **`application/octet-stream`**, 466 KB, `%PDF-` |
| arxiv.org/pdf/1706.03762 | 200 `application/pdf`, 2.2 MB, no redirect |
| doi.org SSRN (2 redirects) | **403 HTML** (bot block) |
| PUC Goias handle (301 http to https) | 200 **HTML landing page** (no PDF link followed) |
| dsjuog.com (4 hops, 5 s) | **429 HTML** |
| europepmc.org `?pdf=render` | **403 HTML** |
| pmc.ncbi.nlm.nih.gov `.../pdf/` (2 x 301) | 200 **1.8 KB HTML** (a challenge page, not a PDF) |

So about 4 of 9 yield a PDF. The PMC redirect Location carries `:443`, which the 80/443 rule must accept.

**What is needed:**
- Allow `application/pdf` and `application/octet-stream`; after download check for `%PDF-` in the first bytes (a 5-byte sniff beats the header).
- Reject `text/html` for the PDF tier, and never parse it as a paper. An HTML landing page is not a paper either. Treat it as "no full text".
- `PoliteClient._send` reads the whole body before returning, and it caps hops against the first host only (its own `ponytail` comment). Step 2b needs: a type check on the headers before streaming the body, a 50 MB cap for PDFs (default is 5 MB), and per-hop host pacing, because DOI links cross hosts.
- 403/429 from a publisher is a block, not an outage; do not retry and do not trip the breaker.
- Do not use `europepmc.org/articles/..?pdf=render` or the PMC `/pdf/` URL; use the JATS tier instead.

## 5. robots.txt

- **Protego 0.7.0** (2026-09-21): BSD-3-Clause, **no dependencies**, Python >=3.10 (classifiers 3.13-3.15; it runs on 3.12), maintained by Scrapy.
- **API (tested):** `rp = Protego.parse(text)`; `rp.can_fetch(url, ua)`; `rp.crawl_delay(ua)` (15.0 for arxiv.org); `rp.request_rate(ua)` (None); `rp.sitemaps`.
- **Cache** per `scheme://host` in the existing `HttpCache` (or a dict) for 24 h (RFC 9309 §2.4: do not use a cached copy for more than 24 h unless the file is unreachable). Fetch `/robots.txt` through `PoliteClient`, with source "robots".
- **Failures (RFC 9309 §2.3.1):** 4xx (including 404) means "unavailable", so everything is allowed (`Protego.parse("")` allows everything, checked). 5xx or a network error means "unreachable", so treat as disallow and retry later. Follow at most 5 redirects.
- Our own `PoliteClient` User-Agent product token is `Researchly`. Honour `Crawl-delay` by feeding it to `HostLimit` (arxiv.org: 15 s).

## 6. Chunking (350 tokens, 15% overlap, per section)

| Option | Licence | Dependencies | Verdict |
|---|---|---|---|
| **semchunk 4.1.1** (2026-06) | MIT | `tqdm` (+`dill` on Windows) | **Chosen.** Accepts any `token_counter` and has an `overlap` argument. |
| chonkie 1.7.0 | MIT | numpy, chonkie-core (Rust), tokie, tenacity, httpx | More than needed. |
| langchain-text-splitters 1.1.3 | MIT | langchain-core | Character-based recursive splitter; token mode needs tiktoken or a custom length function. |
| docling `HybridChunker` | MIT | docling-core `[chunking]` extra: transformers, semchunk <4, five tree-sitter packages | It also works on a DoclingDocument only, so it does not fit HTML/JATS. |
| 15-line `tokenizers` window | none | none | Splits mid-sentence. |

Tested on 39 K characters (9,670 Qwen3 tokens) of the Transformer paper, with the Qwen3-Embedding-0.6B `tokenizer.json` (11 MB, from the HF hub) as the counter:
- `semchunk.chunk(text, chunk_size=350, token_counter=n, overlap=0.15)` produced **52 chunks, max 276, mean 223 tokens, in 0.08 s**.
- A naive sliding window gave 33 chunks of exactly 350, in 0.06 s, but cuts sentences.
- semchunk's `overlap` makes chunks smaller than `chunk_size` (it keeps content plus overlap within the size). To get about 350 content tokens, set `chunk_size` near 400, or accept ~220-280. I found no published retrieval benchmark specific to semchunk; the semchunk README claims it is faster than similar libraries, but I did not verify that. Sentence-aligned chunks are the choice made on the structure, not on a benchmark.

## 7. Throughput

From ADR 0005 (Docling, torch-free, no OCR): **0.7 s per page warm on the dev box** (i7-8700); CI runs 0.5-3.6 s per page by OS (windows-2025 3.57 s, macOS arm64 0.53 s); cold start 4-15 s (model load, 164 MB first download). OCR on an image-only page: 5.5-26 s. A 15-page paper is therefore about 10 s on the dev box and up to 55 s on a slow runner, 3-6 minutes with OCR. HTML (0.4-2.3 s fetch) and JATS (5-19 s fetch) are fetch-bound. arXiv's 15 s crawl-delay alone makes a batch of ten papers 2.5 minutes. **Ingestion must be a background job with progress**, which matches ADR 0005's OCR queue.
